## 部署、限制和回退

默认`compose.inference.yaml`启用Intel专用ICD与renderD128；排除llvmpipe，模型摘要/全层卸载由实际日志与/api/ps确认。每次正式模型响应在记录真实token后核对全量GPU驻留；CPU/部分卸载不默认为合格GPU规划。backend和辅助线程写入新活动冻结配置。控制代码更新后须完成旧冻结活动再adopt；数值身份不变，可保留合法历史分数与排除记忆。

单请求的假设→数学工具→反馈选择存在依赖，保留OLLAMA_NUM_PARALLEL=1。CPU训练、Qwen GPU和规划可同时工作；不通过无用并发制造GPU占用。推理6GiB内存、512MiB tmpfs和256MiB Mesa缓存、一个加载模型、有限队列、有界日志、Next现有GC/存储/租约防卡死保护继续保留，无每日调用/token截停或费用预算。

正常启动：`docker compose -f compose.yaml -f compose.inference.yaml up -d`。只有完成冻结活动、按当前代码adopt后恢复持续调度；不改预测门槛与开奖日17:00准备、18:50封存、19:00最终邮件、19:30内部发送截止。

显式CPU回退：`docker compose -f compose.yaml -f compose.inference.yaml -f compose.inference.cpu.yaml up -d`，恢复Qwen空闲12/繁忙4线程、12CPU上限，移除GPU设备并关闭Vulkan要求。CPU回退不恢复宿主CPU范围，也不打开旧DEHPS。再次使用正常两文件配置即恢复GPU。每次切换均先完成/明确终止冻结活动并记录操作，不允许静默降级。

## 复现范围

`scripts/benchmark-gpu.py freeze`从Next主库只读抽取一份历史快照的元信息与两段已有请求到ignored runtime；不读取旧库，不写研究分数。隔离runner必须CPU0–19、dehpsnext.slice、CPU训练8、BLAS/OMP/MKL=1；提供已有Next私密环境以及Next runtime副本/挂载。CPU服务别名next-inference，GPU探测服务别名next-gpu-bench，均只在Next Docker网络。默认GPU已启用后应另建CPU隔离探测实例，在runner内覆盖next-inference解析；脚本拒绝以GPU服务冒充CPU基线。每组使用新label，已有实际回执不可覆盖；新freeze前先去重导入并清理上轮专属目录。

在隔离runner内运行：

```sh
python scripts/benchmark-gpu.py freeze
python scripts/benchmark-gpu.py trial --backend cpu --qwen-threads 4 --profile concurrent --label cpu-busy
python scripts/benchmark-gpu.py trial --backend gpu --qwen-threads 4 --profile concurrent --label gpu-busy
python scripts/benchmark-gpu.py trial --backend cpu --qwen-threads 12 --profile serial --label cpu-idle
python scripts/benchmark-gpu.py trial --backend gpu --qwen-threads 4 --profile serial --label gpu-idle
```

主对照必须相反次序重复，CPU推理容器额度须与12线程基线一致，GPU推理CPU辅助额度4；暂停研究须在冻结活动边界，测试结束恢复。宿主每秒读coretemp Package id0与GPU频率，预热和整块时间分列。脚本440秒退出上限，响应128KiB/240秒技术限制；返回计数缺失保持未知。每次实际调用回执须去重导入主库token总计，再清理临时库、产物和容器。

初次探测整目录只读挂载遇到Ollama manifest迁移失败，随后改为有界tmpfs元信息和现有权重只读挂载，未复制模型。用户中途将“CPU全占”更正为“GPU全占”，已开始的两组CPU20测量完成并保留回执，其余取消；不纳入主对照平均。未新增单元测试或CI。部署后的实际GPU驻留、持续活动推进、CPU分区、旧服务关闭另作上线核验，不能用隔离通过冒充已部署。
