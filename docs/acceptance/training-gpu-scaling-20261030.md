# 全GPU Qwen之后的训练CPU扩容复测

2026-10-30。结论：保留生产训练8线程/8CPU容量。当前固定训练负载中，提高到12、16或20线程没有足够收益；没有为填满占用率更改生产配置。Qwen继续Intel Vulkan29/29层卸载、CPU辅助4，规划1；Next池CPU0–19，系统保留LP-E20–21。温度、费用、机器寿命不作选择门槛。

## 可比负载与线程筛选

使用前一次GPU对照的同一Next3521期快照、FFT/Newton/ridge三配方、15个合法过去起点。固定hidden128、train_history256，窗口8/32，epochs12/28。每次真实优化器训练都检查参数变化。主库只读，不写科学评分、封存预测或邮件；旧DEHPS没有访问。

每档独立进程，相同数据/种子，容器CPU容量上限与Torch线程匹配，亲和性均0–19。按8→12→16→20→20→16→12→8次序筛选，单次135拟合/3060梯度步，65秒停止线，不把未完成结果记为完成。

| 训练线程/CPU容量 | 同量135拟合耗时，两次 | 判断 |
|---|---|---|
| 8 | 3.91 / 6.14秒，均值5.03秒 | 保留 |
| 12 | 4.34 / 8.78秒，均值6.56秒 | 较高档中最有希望，进入GPU并发复测 |
| 16 | 首次65秒停止，最后确认120拟合；另一次8.78秒 | 慢且波动明显，不将截停值混入均值 |
| 20 | 17.84 / 17.25秒，均值17.55秒 | 明显更慢 |

线程跨档输出不保证按位相同；已完成筛选相对8线程的最大概率绝对差为1.94e-7，同线程复测摘要一致。没有将不同线程的临时分数映射入生产缓存或称为预测能力提升；如将来选中不同线程，仍须在新冻结合同下做完整应用验证。

## 全GPU Qwen并发复测

8→12→12→8反序复测，每块450次拟合/10200梯度步，同时向真实GPU服务发送固定的两段历史研究请求484/485；相同模型摘要、JSON格式、上下文4096、seed1729、GPU辅助4，重新加载/预热另记。四组均完成，PS均确认size_vram=size=1706788125，全部模型层驻留GPU。完整逐次回执、超时和数值差见[JSON证据](training-gpu-scaling-20261030.json)。

| 两次聚合结果 | 8线程 | 12线程 |
|---|---:|---:|
| 训练阶段平均耗时 | 15.35秒 | 17.48秒 |
| 训练活跃阶段拟合/秒 | 29.32 | 25.75 |
| GPU规划两请求平均耗时 | 58.53秒 | 58.48秒 |
| 完整并发块平均耗时 | 58.54秒 | 58.50秒 |

整体仅差0.045秒，小于组内约1秒波动，不作为升级依据；12线程的训练阶段更慢。这个固定块的结束时间由GPU规划主导，不能推广为所有实际活动都仅有GPU瓶颈。12线程多占CPU没有换来本次可用的整体加速，因此不调整统一生产配额。

当前fit_prior是较小网络，compute_node逐个历史起点执行；线程数增加时同步/调度可能抵消并行收益，这是基于结构和耗时的解释，未做内核级剖析。下一种值得单独验证的方向是独立历史起点的进程并行；本PR没有实现该调度变化，也不声称它已经加速。不同窗口、隐藏层或历史长度可能有不同最优值，本次不是所有未来模型的穷举。
