# CPU分区与按训练压力切换本机推理线程

2026-10-30用户授权：只留两个低功耗核给系统，其余交给Next，并按实际训练吞吐选择线程配比。本政策替代之前仅设置8/4/1容器额度的分配。

## 分区与持久化

实机155H的CPU0–11是6个P核的12个逻辑线程，12–19为8个E核，20–21为2个LP-E核。Next的8个容器全部使用cpuset0-19和独立dehpsnext.slice；常规system.slice、user.slice、init.scope限制到20-21。Next的主机遥测代理是轻量宿主任务，随user.slice运行。中断、内核活动不宣称完全隔离，本次不修改启动参数或IRQ策略。

不能仅给Next加cpuset就声称系统已留核，因为其他进程仍可能使用0-19。管理员脚本scripts/cpu-partition.py先prepare独立slice；全部Next容器迁入后，apply才设置宿主组的持久AllowedCPUs。脚本先检查每个Next容器运行、父slice和实际亲和性，保留原宿主AllowedCPUs，支持restore-host回退。主slice在slices.target启动，先于Docker恢复容器。旧DEHPS保持关停，归档代码、历史数据和模型不删除。

## 选择的执行配比

| 工作 | 配置 |
|---|---|
| 预测网络/历史回归训练 | 固定8个Torch线程，8容量CPU上限 |
| Qwen推理 | 12容量CPU上限；请求发起时没有待执行/运行中的计算任务，用12线程 |
| 计算队列繁忙时的Qwen | 请求发起时存在READY/RUNNING且非RESEARCH_PLAN任务，用4线程，优先保护训练吞吐 |
| 规划进程 | 1容量CPU；方向价值网络与预测训练线程保持区分 |
| BLAS/OMP初始环境 | 统一1；Torch训练线程由Worker显式设置，避免嵌套数值库无控制扩展 |

所有额度共享CPU0-19池，瞬时总使用受这个池限制；不是独立物理核心数量的相加。推理线程只在请求开始时选择，不在生成中途取消或改线程；发起12线程调用后新出现的计算任务，会在下一次推理请求使用繁忙档。线程数、最大推理线程和繁忙档写入冻结研究配置，实际请求保留num_thread。状态API报告当前执行策略与进程真实亲和性。

## 实测依据与边界

实际调用fit_prior，从同一3521期Next历史的合法过去前缀训练；FFT、Newton和ridge各使用近期真实配方，固定15个不同起点，多次重复用于测吞吐，不能当作新增独立开奖证据。先筛选2/4/8/12/16，再以独立进程、相反顺序复测4/6/8。每个长块450次真实拟合、12600个梯度步骤，预热另记。

独立复测聚合吞吐：4线程15.21次拟合/秒、6线程13.52、8线程16.83。16线程首个长块仅7.23；第二块超过120秒后停止，未完成工作未记成完成。Qwen使用固定的真实历史研究请求、相同模型/上下文上限/JSON结构，返回计数来自本机服务。4线程一对请求64.71秒，8线程复测平均55.83秒，12线程平均41.40秒；这些是执行时间和结构合法性，不能说明建议质量或命中率提升。

并发资源竞争测试同时执行450次真实拟合和一对Qwen请求：8/4的训练阶段9.76次/秒，8/12仅7.18次/秒；因此计算繁忙时降Qwen为4，而不是始终12。8/12整体竞争块65.48秒，8/4为96.44秒，不能把整体块耗时和训练活跃阶段的拟合吞吐混为一谈。本次选择同时利用单独训练、空闲推理和训练优先三项结果；不是保证任意后续模型形状都最优。

统一单线程BLAS属于数值执行条件改变，使用prior-fit-v2-single-blas的新数值身份；不把旧数值身份的缓存当作新配置的验证。新根节点按近100/近10/分层随机清单重新训练。旧研究经验可用于探索建议，最终父子比较及发布资格必须来自当前数值合同的实际评分。
