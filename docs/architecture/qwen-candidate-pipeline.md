# 去重新候选、失败反馈和有界研究流水线

2026-10-30。延续v1.1；按本轮用户最新修正，新轮仅用最近100期、50期、10期核验，目标为红球Top100红5及以上命中率、蓝球Top1命中率的增量。50%不是改善门槛。旧随机历史协议的冻结实验与事实保留。

## 提案有效性

`candidates-v2`先从完整配方记忆中过滤已登记/已试配方，再用同一数据集、协议、数值版本与线程数的配对反馈训练方向价值网络，选出最多12个候选供Qwen评审。候选覆盖不同方法、窗口、历史长度或网络宽度组合；当前方法族仍是预登记的FFT、ridge和Newton，并非开放执行任意算法。

Qwen只输出所提供的候选ID。双候选使用不相交的选择槽，避免同一回复内重复。模型仍给出调整理由和风险，控制器同时保存实际参数差异，以便区分模型措辞和真实变更。推理后提交时再次检查完整记忆，重复候选不能登记为新方向。

每次评审提供最多6条真实证据，含当前父节点、最近完成的当前轮反馈以及同口径前轮反馈。新协议提供100/50/10的红5+期数、蓝球命中数、对应父子差异和原判定；旧协议保留原指标用于兼容。存在退步或不确定证据时，Qwen必须引用其中一个可验证的证据键；不允许把INCONCLUSIVE改写成PRUNE_REGRESSION。小型数学工具检查仅证明数值实现基本正常，不证明彩票可预测。

新协议按每期此前可用数据独立训练，再由冻结概率生成该期Top100与唯一蓝球，与真实标签比对。红5+命中率的分子是至少一组红球命中5或6个的期数；一期开出多组5+也只算一期。近50、近10嵌套在同一100期内，总共100个独立期次，不计成160期。训练窗口由配方决定，与核验窗口分开；不打乱时间序列，不抽取更早的随机历史验证起点。

两个指标都逐步比较父模型。近100期至少一个命中率提高，并且100/50/10中两个指标均不下降时，记录观察到的开发改善并允许继续子方向；相互取舍或证据不足保留INCONCLUSIVE。配对区间另行记录，小幅观察改善不冒充统计显著或真实前向提升。区间仅在固定100期内估算不确定性，不增加历史样本。新协议没有随机历史追加池；重复跑同一期不算更多独立验证。

正式封存继续执行数据边界、完整概率和基线校准守卫。开发命中率上涨与当期正式推荐资格分别记录。旧模型同数据、同种子、同数值版本和线程的概率评分可取精确100期子集复用，重新计算新业务指标，缓存拟合不算新训练。排名由固定概率决定，实际标签只用于比对，禁止事后挑选Top100。

方向价值网络的训练样本和历史权重均按数据集/协议/数值版本/线程契约隔离，避免用不同比较口径的奖励混训。配方记忆采用稳定顺序。因父节点变化而跳过、确实未训练的候选释放其临时占位，可重新成为合法候选；已经验证的配方不会因此被删除或遗忘。

## 两节点流水线

`DEHPS_NEXT_RESEARCH_AGENT=candidates-v2`选择新控制器，`DEHPS_NEXT_RESEARCH_PIPELINE_DEPTH`只允许1或2，并在每轮配置冻结。深度1为串行对照，深度2最多保留两个尚未完成训练的节点，含正在运行的节点。GPU规划仍最多一个任务，CPU计算仍最多一个任务，并行历史起点保持8进程×1线程、训练配额8 CPU。

根节点评估后，一次Qwen调用可登记两个独立子候选。第一个子节点评估完成后触发下一次规划；此时第二个子节点可继续CPU训练，因此GPU评审与CPU计算发生重叠。规划不创建无界队列；提交事务在研究轮行锁下重新计算剩余容量及节点总预算。达到节点上限时，必须等所有已登记节点完成或明确跳过，才能结束该轮。

每批计划冻结父节点及恢复锚哈希、数据集、协议、控制器版本、数值版本、线程数和当时已见反馈。提交时核对全部边界。父节点因真实验证改善而替换后，旧计划记录DISCARD_STALE_PLAN，旧父节点上未执行的队列项记录SKIP_STALE_PARENT；都不能冒充新训练或验证改善。

同一父节点下，CPU可能在GPU规划过程中产生额外反馈。它们记录为feedback_completed_during_planning，并进入下一次评审；不得声称一个先启动的Qwen调用已经看到了这些后到证据。历史回归使用同一冻结起点，失败按原协议回退，不为提升吞吐放宽评分。

## 17:00与运维

开奖日17:00禁止领取新的训练/规划任务，运行中任务通过原门禁保存检查点并让出。新规划在提交事务前再次检查门禁，17:00后不能把在途推理结果登记为新训练方向。报告等待有效租约收尾，Top100/蓝球Top1完成即发，不等19:00。19:30只作故障兜底；没有合格候选时提供明确的研究参考，正式覆盖缺口保留。只有完整官方开奖号核验后恢复。

Qwen继续全Vulkan GPU、4个CPU辅助线程；Next限定CPU0–19，系统使用LP-E20–21。没有日token或算力用量额度；保留每任务、硬件、内存、存储和租约限制，原GC回收研究细节与推理产物。旧DEHPS保持关闭且代码数据不动。

开启流水线前必须实测整个闭环，而非只看GPU/CPU忙碌量。尤其核显与CPU可能竞争内存带宽，重叠不保证更快。记录有效新方向数、真实改善数、新拟合/梯度数、规划耗时、重叠和总耗时，保留失败和不同配方工作量的限制。

`scripts/benchmark-research.py`只接受专用`dehps_next_qwen_*`库和`runtime/qwen-case-*`目录，使用实际Worker与原评分控制器。prepare、独立compute/planning进程、collect三阶段用于隔离复现；不会运行邮件投递。运行前自行创建Next副本，禁止指向主库或旧DEHPS。串行回退应先排空冻结轮，再将流水线深度设为1并登记release adoption；继续保留去重及失败反馈修复。
