# Evidence-directed parent-frontier research

Generation counts identify bounded experiments, not successive independent draw
samples or guaranteed accumulated forecast skill. Keep the original prior-only
fitter, shared eight-CPU slice, exact recipe exclusions, immutable results,
100/50/10 paired hit promotion and separate formal qualification unchanged.

## Measured direction change

An explicit completed comparison is required before `research_frontier.activate`
can replace the program's topic. The evidence must match the current dataset,
parent recipe and numerical identity. Adopt the reviewed controller and finish
its active frozen campaign first. Append old/new policy and reason to the policy
ledger; preserve the accepted parent, counters, original topic and all negative
experiments. This is permission to investigate a new direction, not a claim that
the direction already improves forecasts.

The four shared-frequency families were the exclusive active search space and
could not borrow the retained ridge parent's representation. Changing learning
rate/regularization/history in that space did not address repeated red5+ vetoes.
The new space keeps actual parent structure as its reference and registers
32-recipe questions: finer coupled regularization, history/capacity, and causal
representation. Each batch records its parent, cursor, question and completed
verdicts. At least24 completed outcomes without joint improvement move the next
block to a different question. An actual parent improvement restarts its local
frontier. Immutable improvement events take precedence over a recipe registry
entry later reused as a baseline. This is a finite question allocation, not a
daily/lifetime cap; work continues automatically and unselected recipes carry on.

The same exact novelty filter is used by primary planning, Qwen alternatives and
opportunistic CPU continuation. Cached historical scores, imported pilot evidence
and genuinely new origin fits remain distinct. Existing Qwen qualification,
profile, production cadence and per-node feedback receipts are unchanged.

The steward appends one idempotent `BATCH_QUALITY_REVIEW` event for each completed
owned frontier campaign. It records each candidate's actual parent,100/50/10
red/blue counts, exact paired deltas, execution receipts, promotion result and a
digest of the source facts. It separately counts red vetoes, blue vetoes, absent
recent progress and recent gains vetoed by nested windows. Skipped nodes are not
evaluations. These immutable reviews survive optional graph retirement and do
not add independent draw labels or change model eligibility.

At a non-improving block boundary, use up to four recent reviews matching the
current dataset, numerical identity and parent recipe. At least24 reviewed
candidates are required for a cause-directed question change. Red veto dominance
prefers capacity or representation; blue dominance prefers representation or
history, avoiding the question just tried. Tied or insufficient review coverage
uses the registered sequence. Parent improvements retain priority. Record the
review event IDs, diagnostic counts and reason in the next proposal batch.

## Direction-comparison evidence

Use Next-only datasets and isolated Python3.12/real Next PostgreSQL for frozen
comparisons. Match the retained parent's complete per-origin scores before any
cache reuse. Register performed negative pilot recipes so they are not rerun as
new ideas; store source database, study/driver/data hashes and cache receipts.
Never overwrite earlier results or call an earlier historical window forward or
universally untouched holdout evidence. Probability blending/portfolio-selection
ablations are cached-score analyses, not new fits or approved output rules.

Lower probability loss, larger uniform-space coverage, or a gain on a different
historical block cannot substitute for the original paired hit gates. Failed
alternatives stay out of canonical report selection. No dashboard, test mail,
legacy access, unit tests or new CI are introduced.
