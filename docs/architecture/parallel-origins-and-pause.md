# 独立历史起点并行与17:00收尾

2026-10-30最新用户要求，覆盖之前18:50封存、19:00发送的规则。

开奖日上海时间17:00开始暂停新的训练与研究规划，正在运行的任务在有限步骤内停止并保存已完成起点。随后立即复核、封存并发送邮件，不等待19:00。报告包含红球Top100与唯一蓝球Top1；无合格候选时仍提供明确标注的研究参考，不补造合格推荐。19:30只保留为故障兜底截止。收到并核验当期完整官方开奖号后才恢复；跨零点、仅到开奖时间、旧导入号码都不能解除暂停。非开奖日持续研究。

暂停会阻止TRAIN、RESEARCH_EVALUATE、RESEARCH_PLAN领取新工作；SEAL、EVALUATE和邮件结算仍可执行。运行中的计算约每0.5秒检查门禁，进程池合作取消；已完成的有序前缀写入租约保护的检查点，未完成部分恢复后重算。Qwen请求受既有单次时限约束，暂停后不能提交新研究方向。报告等待有效运行租约收尾；旧失效租约不能无限阻塞报告。每30秒运行一次reporter，正常收尾完成后下一轮就排队并发信，没有19:00等待条件。

每个历史起点是独立训练，spawn子进程只收到该起点之前的数据、固定配方及独立种子。目标标签留在父进程评分。原fit_prior、优化器、父锚恢复和评估门槛不变；父锚发布仍独立完成。最多8个待处理起点，不创建无界队列或每起点模型文件。温进程池跨节点复用，暂停/退出/租约丢失时关闭；无法在5秒内关闭则进程退出，由容器命名空间回收全部子进程。

选用8个起点进程，每个1个Torch线程，训练容器合计8 CPU、6GiB、256 PID。Qwen保持全Vulkan GPU、4个CPU辅助线程，规划1 CPU；Next仅CPU0–19，LP-E20–21留给系统。配方及数值线程在每轮冻结，完成旧轮后才能切换配置。分数缓存包含数值线程；原8线程分数不能冒充1线程重训结果。保留配方记忆用于方向选择，候选仍在当前数值契约下重新验证。

精确源文件哈希的数值兼容映射只覆盖已审计版本，未来未审计代码自动获得新标识。同一线程数下串行与并行的评分、锚参数、优化器、RNG已逐字段核对；不同线程数不承诺位级一致。全部证据属于工程验收与开发回放，不是预测能力或50%目标的证明。

无合格候选时优先采用17:00前完成的兼容神经网络锚生成研究参考；若没有可用锚，使用同一合法数据边界的历史频率基线，明确标注来源。整份参考随不可变PRE_FINAL冻结，开奖后按该冻结号码逐项复盘。参考命中与合格推荐统计分开，正式覆盖缺口保留。

## 运维与回退

正常配置：`docker compose -f compose.yaml -f compose.inference.yaml ...`。

串行起点回退：先停止steward并排空当前冻结轮，再增加`-f compose.origins.serial.yaml`，保留全GPU推理及17:00政策。若需CPU推理回退，再增加`-f compose.inference.cpu.yaml`；这两项回退相互独立。变更后登记release adoption再恢复自动调度。不要在冻结轮中途修改数值线程或进程数。

复测可在专用`dehps_next_parallel_*`数据库与`runtime/parallel-*`副本运行`scripts/benchmark-origins.py --campaign ... --processes 8 --threads 1 --label ...`；它只用于计算筛选，拒绝主库并遵守真实开奖暂停。完整闭环还需运行实际Worker、Planner、Steward并统计Qwen规划、验证、剪枝、恢复和下一轮。固定输入对照与自由研究结果应分别记录，不能只看CPU占用率。

数据库迁移010更新17:00封存守卫，数据库真实时钟没有配置覆盖。历史封存、邮件与结算事实不改写；隔离验收的历史时钟仅存在于专用数据库，验收结束恢复默认时钟。日历目前覆盖至2026-12-31，超界暂停并提示复核，不猜测新日历。
