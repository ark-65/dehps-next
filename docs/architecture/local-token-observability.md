# 本地Qwen只做token统计，不做用量计费或额度截停

2026-10-29 用户明确要求：本地部署不考虑按消耗计费；只报告产生的token。此政策覆盖之前691200容量秒/24次调用的日额度约定，旧记录保留为历史，不再参与准入。

## 有效辅助的实际证据与边界

现存29次成功调用记录中，输入46435、输出7005，合计53440 tokens。Qwen参与提出并执行过13个分支，4次被当时的开发协议接受，对应3种不同配方；没有证明这些选择提高了真实前向命中率。部分解释存在对方法或反馈的误读，因此模型文字从不覆盖固定评分器。

最近autonomous-v2在本次修改前没有新的Qwen调用。旧日调用计数23/24，而一个完整决策需2次调用，导致它实际被限额旁路。旧60秒技术超时也会拒绝较慢但最终完整的本地响应。这里没有外部推理API账单，先前“计费/容量消耗”措辞和每日额度设计不适合用户要求。

## 执行政策

- 移除按日容量秒、调用次数、token用量及活动内调用额度的准入条件，不再累加新的容量秒费用账。旧资源账本保留，原cap字段置NULL并标记OBSERVE_ONLY_TOKENS。
- 保留训练8核、Qwen最多4核、规划1核，以及内存、磁盘、应用产物、并发通道、正式任务优先级和租约保护。
- Qwen在根节点和每增加3条实际实验观测后参与复审，其余步骤由方向网络选择新配方。这个节奏基于新证据，不是用量额度。后端故障仍短退避，防止卡死。
- 单次响应上下文/长度与超时属于技术边界：4096上下文、最多2048输出token、请求180秒、规划尝试420秒。达到单次技术边界不会把整日研究按消耗停掉。
- 本地假设全是已试配方时，保留真实模型调用记录并转向尚未尝试的注册方向，不能把重复提案误报为所有研究空间耗尽。
- 新完成的研究批次称BATCH_COMPLETE，随后继续调度；旧BUDGET_EXHAUSTED事件不改写。

## token回执

以Ollama返回的prompt_eval_count和eval_count为准，分别显示输入和输出，合计仅为已记录用量，不是货币。请求得到回执后先保存token，即使JSON无效、输出截断或任务失去租约也保留实际生成量。没有回执时标未报告，不根据字符数猜测。

每个调用支持恰好一次入账以及未知回执到已知回执的修复；已知计数冲突不能静默覆盖。最近32天按模型/日聚合，另有不随研究明细GC丢失的累计统计。工作进程丢失后明确标记未知，不能写成0 token成功。已有记录可回填，更早没有保留回执的用量不补造。

只读status和`dehps-next token-usage`显示token；不再显示旧日额度/容量扣费。正常PRE/POST邮件附token汇总，不另发用量通知，不改写已发送邮件。旧budget-set管理命令明确退役。

## Qwen输出权威性

提示和跨主题反馈明确区分选中父模型、方法名、配对判决和备用清单；只提供同数据/协议/线程的近期跨主题对照。模型提出候选，实际神经网络训练、近100/近10/随机历史验证和独立状态控制器决定接受、回退或换方向。4次历史开发接受不等于4次独立科学发现，token更多也不等于预测更准。

旧DEHPS不操作。正式封存、业务命中口径和邮件时间保持不变。
